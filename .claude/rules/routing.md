# Entry points, build, routing

## Build and entry points

- `vite.config.ts` plugins, in order: `devtools()` (must stay first), `nitro()`, `tailwindcss()`, `tanstackStart()`, `viteReact()`, `babel({ presets: [reactCompilerPreset()] })`. The last one turns on the React Compiler for the whole app. `resolve: { tsconfigPaths: true }` resolves the `@/*` alias.
- Start finds its entries by file name in `src/`: `router.tsx` (required, exports `getRouter()`), `start.ts` (optional, doesn't exist yet — see `server.md`), and client/server entries (absent, so Start's defaults are used).
- Nitro is the server adapter, with its default Node preset: `pnpm build` writes the server to `.output/`, and `pnpm start` runs `.output/server/index.mjs` on port 3111.

## Router and SSR shell

- `getRouter()` (`src/router.tsx`) builds the router context with `getContext()` — a new `QueryClient` per request — and calls `setupRouterSsrQueryIntegration` (both in `data-fetching.md`). It registers the router type through `declare module '@tanstack/react-router' { interface Register { router } }`.
- Router options: `defaultPreload: 'intent'`, `defaultPreloadStaleTime: 0` (React Query owns freshness; without it the router's own preload cache double-caches), `scrollRestoration: true`.
- `src/routes/__root.tsx` uses `createRootRouteWithContext<AppRouterContext>()({ ... })` — note the **double call**: first with the context type, then with route options. `AppRouterContext` (`src/integrations/tanstack-query/context.ts`) is `{ queryClient: QueryClient }`; widening it means updating that interface and the object returned by `getContext()`.
- The root route renders the whole document via `shellComponent: RootDocument` (`<html>`, `<HeadContent />`, `<Scripts />`), linking the stylesheet from `head` through `styles.css?url`. Inside `<body>` it renders `ThemeProvider` around the page and `<TanStackDevtools>` — both described in `integrations.md`. `<html>` carries `suppressHydrationWarning` because the theme script sets its class before hydration.
- **Head/meta**: the root `head` sets `charSet`, `viewport` and a hard-coded title (`'TanStack Start Starter'`). Child routes set `head: () => ({ meta: meta({ title: 'Page' }) })`, where `meta()` from `@/integrations/tanstack-router/utils` produces `'Page - <VITE_APP_TITLE>'`.

## Routes

File-based routing in `src/routes/**`: flat dot-separated names at the top level, a nested directory for `components/`; `(group)` folders work too.

| File | Path | What |
| --- | --- | --- |
| `index.tsx` | `/` | Placeholder home page |
| `components/route.tsx` | `/components` | Layout of the preview pages: `AppNavbar` + `max-w-5xl` container |
| `components/index.tsx` | `/components/` | List of preview pages |
| `components/data-table.tsx` | `/components/data-table` | TanStack Table preview (see `features.md`) |
| `components/file-upload.tsx` | `/components/file-upload` | `FileUpload` preview (see `features.md`) |
| `components/form.tsx` | `/components/form` | TanStack Form preview (see `features.md`) |
| `components/rich-text-editor.tsx` | `/components/rich-text-editor` | Lexical rich text editor preview, `ssr: false` (see `features.md`) |
| `api.$.ts` | `/api/$` | oRPC OpenAPI handler — REST surface, docs and spec (see `server.md`) |
| `api.rpc.$.ts` | `/api/rpc/$` | oRPC RPC handler — what the browser client talks to (see `server.md`) |

- **Breadcrumbs**: a route sets `staticData: { breadcrumb: 'Label' }` (typed by the `StaticDataRouteOption` augmentation in `src/integrations/tanstack-router/tanstack-react-router.ts`); `RouteBreadcrumb` lists every match that has one.
- **Client-only pages (`ssr: false`)**: Start skips loading the route's component chunk on the server and wraps the match in `ClientOnly`, rendering the route's `pendingComponent` as the server/first-paint fallback; `head()` still runs on the server, so the title is in the HTML. `/components/rich-text-editor` uses this because the Lexical editor can't render on the server; keep the `pendingComponent` free of browser-only imports.

Routes that own their data wire it through a loader as described in `data-fetching.md`.

## Route tree generation

- `src/routeTree.gen.ts` is generated by the router plugin inside `tanstackStart()` — never hand-edit it. It's excluded from Biome checks and marked read-only in `.vscode/settings.json`. Its footer (`declare module '@tanstack/react-start' { interface Register { ssr, router, … } }`) is written only by the Start plugin; once `src/start.ts` exists, the footer also imports `startInstance` from it to register `config`.
- New route files are picked up automatically while `pnpm dev`/`pnpm build` is running. Without a dev server, run `pnpm generate-routes` after adding a route and before `pnpm validate:full`, so `tsc` sees the new `createFileRoute` path and `Link to` values — a generation step, not verification.
- Caveat: `tsr generate` (`tsr.config.json` only sets `target: 'react'`) doesn't know about Start and **drops that footer**, so Start's `Register` is missing until the next dev/build run restores it. Type errors about Start's registered router or global middleware context right after `generate-routes` come from that, not from your change; don't hand-write the footer back.

## Known gaps and leftovers

Scaffold leftovers and half-finished work. **Do not assume these are intentional**, and don't spend time re-deriving them:

- **English where the UI copy rule says Indonesian:** `<html lang='en'>` in `__root.tsx`, and the `/` page is still the scaffold's English placeholder ("Welcome to TanStack Start").
- **Hard-coded root title:** `'TanStack Start Starter'` instead of `env.VITE_APP_TITLE`, which `meta()` uses for child routes.
- **Stale README:** `README.md` is the generator's template. Its `node dist/server/index.mjs` is wrong (the server is `.output/server/index.mjs`), and it mentions demo pages in `src/routes/demo/` that don't exist.
- **Leftover config:** `nitro({ rollupConfig: { external: [/^@sentry\//] } })` externalizes Sentry, which isn't installed.
